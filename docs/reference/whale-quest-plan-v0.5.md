# Whale Quest 제작 계획 (v0.5)

> NWEC 26 바이브코딩 공모전 출품용 · 분야 1 수업 지원·학습 활동
> v0.4 대비 주요 변경: 교육 문제 정의 신설, 웨일 서비스 연계를 첫 버전 범위에 포함, 1차 MVP·본선 완성본 2단계 구조로 재편, 수업 적용·부스 체험·산출물 계획 추가

## 1. 목표와 완성 범위

**웨일 사이드바에서 운영하는 실시간 수업 도구와 학생 개인 복습을 하나의 문제 엔진으로 연결하고, 웨일 클래스·팀보드와 이어지는 '한 차시 수업 순환'을 만든다.**

공모전은 코드 완성도보다 아이디어와 현장 실현 가능성을 심사한다. 그러나 작동하는 도구가 실현 가능성의 가장 강한 근거이므로, **서류 접수 시점에 실제 수업에서 쓸 수 있는 MVP를 함께 제출**한다. 기준 규모는 **한 학급 30~50명**이다.

| 구분 | 1차 MVP (서류 접수) | 본선 완성본 | 후속 버전 |
|---|---|---|---|
| 교사 수업 도구 | 웨일 사이드바, 타이머, 랜덤 뽑기, 모둠 편성 | 투표, 질문함, 수업 결과 로컬 저장 | 룰렛 |
| 수업방 | 코드·QR 입장, 무로그인 참여, 종료 | 재접속 복구, 전송 대기 표시 | 동시 수업방 확대 |
| 실시간 활동 | 이해도 체크, 빠른 확인(객관식·OX) | 형성평가, 단답형, 문항·성취기준별 통계 | — |
| 협동 레이드 | 보스 HP, 정답 기여, 5분 진행, 전자칠판 표시 | 결과 화면, 동시·중복 제출 검증 완료 | 타워 디펜스 등 다른 게임형 |
| 문제 관리 | 직접 작성, JSON 가져오기, AI 문제 생성 프롬프트 템플릿, 교사 검수 화면 | 문제 공유 링크·QR, 성취기준 코드 | UBT 호환 내보내기 |
| 개인 학습 | — | 집중 학습, 오답 복습, 오늘의 복습, 학습 완료 카드, JSON 백업·복원 | 개인 아케이드, 캐릭터 성장 |
| 웨일 연계 | 클래스 공지 문안 생성, 팀보드용 오답 카드 텍스트 | 5장의 본선 목표 수준 | 웨일 스페이스 계정 연동 |
| 현장 운영 | 예제 문제 세트 2종, 빠른 시작 안내 | 교과별 예제 4종, 부스 체험 모드, 관리자 일괄 배포 가이드 | 웨일 스토어 등록 |

앱 내부 AI, 결제, 광고, 공개 개인 순위는 어느 버전에도 구현하지 않는다.

제공 PRD와 [공유 대화](https://chatgpt.com/share/6abcf32a-2acc-83ee-a1db-b59b8d6e992c?no_universal_links=1)에서 확인한 초기 제안·마지막 수정 내용을 반영한다. 공유 페이지의 중간 전체 발화는 확인하지 못했으므로 세부 요구사항은 제공 PRD를 기준으로 한다. 문서 버전은 본 문서(v0.5)로 통일한다.

## 2. 해결하려는 교육 문제

**형성평가가 '하고 끝나는' 활동에 머물고, 수업 도구가 흩어져 수업 흐름이 끊긴다.**

- **결과가 다음 학습으로 이어지지 않는다.** 정답률은 화면에 잠깐 보이고 사라진다. 누가 어떤 개념을 틀렸는지 교사가 다시 정리해야 하고, 틀린 학생은 오답을 다시 볼 기회 없이 다음 차시로 넘어간다.
- **순위 중심 게임이 일부 학생의 참여를 위축시킨다.** 속도와 점수로 경쟁하는 퀴즈는 상위권 몇 명의 무대가 되기 쉽고, 느리거나 자주 틀리는 학생은 참여를 포기한다.
- **도구를 오가느라 수업이 끊긴다.** 타이머, 모둠 편성, 랜덤 뽑기, 퀴즈, 협업 보드를 각각 다른 사이트에서 연다. 교사는 탭을 오가며 흐름을 놓치고, 학생은 매번 새로운 접속 방법을 익혀야 한다.

수업 적용 전 교사·학생 사전 설문으로 위 문제를 뒷받침해 기획서에 넣는다(11장).

## 3. 해결 아이디어와 창의적 접근

**차별점은 퀴즈 자체가 아니라, 한 차시 안에서 '평가 → 협동 → 성찰 → 재학습'이 닫히는 순환 구조다.**

```
① 수업 전 배포      웨일 클래스 공지에 문제세트 링크·QR 게시
      ↓
② 이해도·형성평가   웨일 사이드바에서 운영, 서버 자동 채점
      ↓
③ 협동 레이드       정답이 학급 공동 HP를 깎음, 순위 없음
      ↓
④ 오답 모둠 성찰    오답 상위 3문항 → 팀보드 카드로 토론
      ↓
⑤ 개인 오늘의 복습  오답 재도전 → 학습 완료 카드를 웨일 클래스에 제출
      ↓
⑥ 교사 확인         완료 카드·성취기준 통계로 다음 차시 문항 조정 → ①
```

- **협동 레이드:** 정답 하나하나가 같은 크기로 학급 목표에 기여한다. 개인 순위·콤보 배율이 없고 오답 후 정답도 기여해, 느린 학생도 끝까지 참여한다.
- **오답의 재활용:** 많이 틀린 문항이 모둠 토론 과제와 개인 복습으로 자동 연결된다.
- **사이드바 운영:** 웨일 클래스나 수업 자료 화면을 띄운 채 옆에서 수업 도구를 조작한다.

## 4. 화면 역할

| 화면 | 사용자 | 역할 |
|---|---|---|
| 사이드바 | 교사 | 현재 수업, 타이머·모둠·랜덤 뽑기, 활동 시작·종료. 복잡한 편집·분석은 웹앱에서 연다 |
| 교사 대시보드(웹) | 교사 | 문제 편집·가져오기·검수, 학생별 응답, 통계, 내보내기 |
| 학생 홈(웹) | 학생 | '수업 참여'와 '혼자 학습하기'를 명확히 구분. 개인 학습 경로에는 교사용 메뉴 없음 |
| 전자칠판 | 학급 전체 | 학급 집계와 레이드만 표시. 학생별 답안·이해도는 교사 전용 화면에서만 제공 |
| 부스 체험 모드 | 참관객 | 3문항 레이드 자동 반복(12장) |

- **게임:** 레이드는 React와 SVG/CSS로 구현한다. 문제 출제·채점은 공통 엔진이 담당하고, 게임은 결과를 받아 표현한다.
- **디자인:** 딥블루·시안 계열과 자체 해양 캐릭터를 쓴다. 기능 중심 한글 메뉴, 모바일 큰 버튼, 동작 줄이기를 적용한다.

## 5. 웨일 교육 서비스 연계

**Whale Quest는 웨일 클래스·팀보드·웨일온을 대체하지 않고, 그 사이의 '형성평가와 복습' 구간을 채운다.** 본선 심사가 웨일 스페이스·클래스·팀보드의 연계성과 완성도를 명시하므로, 연계는 시연 가능한 기능으로 만든다.

| 웨일 서비스 | 수업 단계 | 연계 기능 | 1차 MVP 수준 | 본선 목표 수준 |
|---|---|---|---|---|
| 웨일 클래스 | 수업 전 | 문제세트 배포 | 공유 링크·QR과 과제 공지 문안 자동 생성 | 클래스에서 외부 도구로 바로 실행(주최 확인 후) |
| 웨일 클래스 | 수업 후 | 개인 복습 회수 | — | 학습 완료 카드(이미지) 생성 → 과제로 제출 |
| 웨일 클래스 | 수업 전 | 명단 활용 | 명단 붙여넣기 → 랜덤 뽑기·모둠 편성(로컬 저장) | 동일 |
| 팀보드 | 수업 후 | 오답 모둠 토론 | 오답 상위 3문항을 카드용 텍스트로 복사 | 카드용 이미지·텍스트 일괄 내보내기, 모둠 편성 결과 복사 |
| 팀보드 | 수업 후 | 질문함 정리 | — | 익명 질문을 카드용 텍스트로 일괄 내보내기 |
| 웨일온 | 수업 중 | 원격·혼합 수업 | 전자칠판 집계 화면을 화면 공유 | 원격 수업 시나리오 시연 |
| 웨일 스페이스 | 도입 | 설치 부담 제거 | 웹 링크만으로 참여 | 관리자 일괄 배포 가이드 |
| 웨일 UBT | 평가 | 역할 분담 | 문항 성취기준 코드 필드 | 성취기준별 '평가 전 복습 세트' |

연계 원칙은 다음과 같다.

- 학생 개인 데이터를 웨일 서비스로 자동 전송하지 않는다. 교사가 확인하고 복사·게시하는 방식이 기본이다.
- 웨일 클래스·팀보드 화면의 내용을 읽어 오는 방식(DOM 스크래핑)은 쓰지 않는다.
- UBT는 총괄·수행평가, Whale Quest는 과정 중심 형성평가와 보충 학습으로 역할을 나눈다. UBT 평가 환경에서는 동작하지 않는다.
- 외부 링크 삽입, 임베드, 외부 도구 등록, 계정 연동의 지원 범위는 주최 측 확인 후 본선 목표 수준을 확정한다.

## 6. 기술 구조

**React + TypeScript + Vite를 공통 기반으로 사용하고, 웹 링크 하나로 모든 기능이 동작하게 한다. 웨일 확장앱은 교사의 '더 편한 진입로'로 둔다.** 다른 교사가 설치 없이 5분 안에 시작할 수 있어야 한다.

| 구성 | 역할 |
|---|---|
| `apps/web` | 학생 참여·개인 학습, 교사 문제 편집·대시보드, 전자칠판, 부스 체험 모드 |
| `apps/extension` | 웨일 사이드바, 수업 도구, 방 생성·활동 제어, 웹앱 연결 |
| `packages/*` | 공통 UI·타입, 문제 검증·채점, 학습 기록, 서버 통신, 내보내기(클래스 문안·팀보드 카드) |

- 정적 웹앱은 Vercel, 실시간 데이터는 Supabase(**서울 리전**), 개인 문제와 학습 기록은 IndexedDB에 저장한다.
- 서버가 필요 없는 기능(타이머, 모둠, 랜덤 뽑기, 개인 학습)은 실시간 서버에 의존하지 않는다.
- 화면 폭 360px(휴대폰)부터 전자칠판까지 반응형으로 만든다.

확장앱은 Manifest V3와 `sidebar_action`으로 구성하고, `action`을 함께 선언하지 않는다. 공식 문서의 설치 조건을 적용한 뒤 실제 웨일에서 검증한다. [웨일 매니페스트 문서](https://developers.whale.naver.com/api/extensions/manifest/)

## 7. 구현 전에 보완할 핵심 설계

### 무로그인 참여와 권한 보호

회원가입·로그인 화면은 만들지 않되, 실시간 기능을 쓸 때 내부적으로 익명 세션을 발급한다. 방 생성자는 교사 권한, 코드로 입장한 사람은 학생 권한을 갖고, 권한은 서버의 방 소유·참여 관계로 판단한다.

- 6자리 코드는 **입장 수단**이며 교사 관리 권한을 주지 않는다.
- 학생은 자기 응답만 제출하고, 다른 학생의 답안이나 교사 화면에 접근할 수 없다.
- 전자칠판에는 집계만 읽는 별도 권한을 부여한다.
- 확장앱에서 웹 대시보드를 열 때는 일회용·단기 연결 코드로 권한을 전달한다. 장기 세션 토큰은 URL에 넣지 않는다.
- 공개 테이블과 실시간 채널에 권한 검사(RLS)를 적용하고 서버 비밀 키는 브라우저 번들에서 제외한다.

Supabase 익명 인증의 기본 IP 제한이 학교 공동망과 행사장 와이파이에서 입장을 막을 수 있다. 동일 IP 50명 입장을 검증하고 제한값·남용 방지를 함께 설정한다. [익명 인증 문서](https://supabase.com/docs/guides/auth/auth-anonymous)

### 문제·답안 인터페이스

PRD의 `AnswerEvent.correct`는 학생이 정답 여부를 조작할 수 있으므로 제거한다.

| 인터페이스 | 결정 |
|---|---|
| `QuestionSet` | JSON 1.0 형식을 유지하고 문제 유형별 정답 형식을 명확히 정의. **문항별 `standard`(성취기준 코드, 예: `[4수01-03]`)와 `tags` 필드 추가** |
| `AnswerSubmission` | 활동 ID, 문제 ID, 실제 답안, 제출 ID, 풀이 시간 전달 |
| 서버 채점 결과 | 정오답·기여량·갱신된 진행 상태 반환. 학생 신원과 태그는 서버에서 확인 |
| `RoomSnapshot` | 현재 활동, 진행 상태, 집계, 레이드 상태, 상태 버전 제공 |
| 로컬 학습 기록 | 문제 세트 버전과 문제 ID를 함께 저장해 수정 전후 기록 혼동 방지 |

객관식은 선택지 인덱스, OX는 불리언, 단답형은 허용 정답 목록으로 판정한다. 단답형은 유니코드·앞뒤 공백을 정규화하고, 동의어나 수학적 동치는 작성자가 허용 답안으로 지정한다.

JSON 가져오기는 문항별 오류를 보여 주고, **교사가 정답·표현을 확인한 문항만 저장**한다. 외부 생성형 AI에서 바로 이 형식이 나오도록 **문제 생성 프롬프트 템플릿**을 함께 제공한다. 실시간 활동은 서버가 채점하고, 개인 학습은 같은 규칙으로 로컬 채점한다.

### 실시간 상태와 협동 레이드

- 방에서는 한 번에 하나의 활동을 실행한다. 활동마다 ID를 발급해 이전 활동의 늦은 제출이 섞이지 않게 한다.
- 제출 ID와 출제 회차로 중복 처리를 막는다. 답안 저장·통계·보스 HP 변경은 하나의 트랜잭션으로 처리한다.
- 재접속하면 현재 서버 상태를 다시 읽고 동일 참여자로 복구한다. 확인되지 않은 제출은 '전송 대기'로 표시한다.
- 레이드는 정답당 동일 기여량을 적용한다. 학생별 동일 문제의 피해 기여는 활동당 한 번으로 제한하고, 오답 후 정답 성공도 기여할 수 있게 한다.
- 기본 레이드 시간은 5분, 목표 HP는 시작 인원과 문항 수의 70% 정답 달성량으로 계산한다. 개인 순위와 콤보 배율은 적용하지 않는다.
- 레이드 종료 시 **오답 상위 3문항과 선택지 분포**를 계산해 팀보드 카드 내보내기에 넘긴다.
- 서버 집계 상태를 최대 초당 한 번 묶어 전송하고 화면에서 부드럽게 보간한다. 개별 답안 전체를 학생들에게 전파하지 않는다.

Supabase Free 한도는 동시 연결 200개·초당 메시지 100개이므로, 첫 운영은 **동시 활성 수업방 1개·학생 최대 50명**으로 제한한다. 월간 사용량과 부하 시험 결과를 확인한 뒤 확대한다. [실시간 제한 문서](https://supabase.com/docs/guides/realtime/limits)

### 개인 학습과 보존 정책

- 오늘의 복습은 최근 오답 → 반복 오답 → 미완료 문항 순으로 구성하며, 기본 20문항으로 중복을 제거한다.
- 오답을 재도전해 맞히면 복습 완료로 표시하고, 다시 틀리면 오답 목록으로 되돌린다.
- 복습을 마치면 정답률, 복습 완료 수, 성취기준 태그가 담긴 **학습 완료 카드(이미지)**를 만들어 웨일 클래스 과제로 제출할 수 있게 한다. 이름은 학생이 직접 적는다.
- 문제 공유는 서버에 저장한 읽기 전용 문제 세트의 짧은 링크·QR로 구현한다. 학생이 가져온 사본과 기록은 로컬에 유지한다.
- 방은 생성 24시간 후 만료한다. 원시 응답은 종료·만료 24시간 후 삭제하고, 필요한 수업 요약은 교사가 로컬에 저장한다.
- 공유 문제는 기본 30일 후 만료한다. 교사의 원본 문제와 학생이 가져온 사본에는 영향을 주지 않는다.
- 개인 기록은 계정·기기 간 동기화 없이 해당 브라우저에 저장한다. 공용 PC에서는 기록이 남지 않는다는 점을 안내하고 JSON 백업·복원을 제공한다.

## 8. AI 윤리·안전성·연령 적합성

**학생 개인정보를 수집하지 않고, 초등 연령에 맞는 참여 방식을 기본값으로 둔다.**

- **데이터 보호:** 학생은 번호·별명으로 참여하며 실명·연락처·이메일을 받지 않는다. 응답 원본은 24시간 후 삭제하고, 개인 학습 기록은 학생 브라우저에만 저장한다.
- **연령 적합성:** 개인 순위를 어디에도 표시하지 않는다. 레이드는 1회 5분 이내로 운영해 과몰입을 막는다. 큰 버튼, 짧은 한글 메뉴, 동작 줄이기로 저학년도 혼자 조작할 수 있게 한다.
- **AI 활용:** 앱 안에서 학생이 AI와 직접 대화하는 기능은 두지 않는다. AI로 만든 문항은 교사 검수 후에만 저장한다.
- **평가 공정성:** 웨일 UBT 평가 환경에서는 확장앱이 동작하지 않도록 한다.
- **바이브코딩 투명성:** 개발에 쓴 AI 도구, 주요 프롬프트, 사람이 검토·수정한 지점을 개발 기록으로 남긴다. AI가 만든 코드는 보안·개인정보 점검표를 통과한 뒤 배포한다.

## 9. 개발 순서와 단계별 완료 조건

**관문 A(서류 접수)까지 1차 MVP를, 관문 B(본선 리허설)까지 수업 적용과 본선 완성본을 끝낸다.** 관문 조건을 통과하지 못하면 다음 단계 기능을 추가하지 않고 범위를 줄인다. 날짜는 공모 일정 확인 후 채운다.

| 단계 | 구현 내용 | 다음 단계로 넘어가는 기준 |
|---|---|---|
| 0. 준비 | 주최 측 연계 방식 문의, 사전 설문, `QuestionSet`(성취기준 포함) 확정, 작업공간 구성 | 연계 가능 범위 확인, 문제 형식 확정 |
| 1. 기반·확장앱 | 공통 타입, 기본 UI, MV3 사이드바, 새 탭 연결 | 실제 웨일 설치·실행, 390~590px 표시 확인 |
| 2. 수업 도구 | 랜덤 뽑기(명단 붙여넣기), 모둠 편성·수정, 타이머, QR 저장 | 서버 없이 동작, 사이드바를 닫아도 시간·설정 유지 |
| 3. 실시간 수업방 | 익명 세션, 권한, 코드·QR, 입장·종료 | 교사 1명·학생 3명 연결, 타인 방 접근 차단 |
| 4. 참여 활동 | 이해도 체크, 빠른 확인(객관식·OX), 기본 현황 | 응답·집계·활동 전환, 개인 정보 비공개 확인 |
| 5. 레이드·연계 기본 | 레이드 HP·기여량, 전자칠판, 클래스 공지 문안, 팀보드 오답 카드 텍스트, 프롬프트 템플릿 | 한 차시 순환 E2E 통과 |
| **관문 A** | 기획서, 시연 영상, 빠른 시작 안내, 보안 점검표 | 처음 보는 교사가 안내 없이 수업방 생성→레이드까지 완주 |
| 6. 수업 적용 시작 | 본인 학급부터 적용, 측정 지표 수집 | 첫 적용 회차 완료 |
| 7. 평가·개인 학습 | 형성평가, 단답형, 성취기준 통계, 재접속 복구, 집중 학습, 오답·오늘의 복습, 학습 완료 카드, 문제 공유 | 수업방 없이 학습, 브라우저 재시작 후 기록 유지 |
| 8. 연계·현장 완성 | 연계 본선 수준, 투표·질문함, 부스 체험 모드, 관리자 배포 가이드, 접근성 | 연계 시연 시나리오 통과 |
| **관문 B** | 수업 적용 보고서, 부하 시험, 부스 리허설 | 50명 동시 입장·답안 제출 통과, 부스 20명 리허설 통과, 2개 학급 이상 적용 완료 |

대시보드는 마지막에 한꺼번에 만들지 않고 각 활동과 함께 확장한다. 개인 아케이드와 룰렛은 본선 이후로 미룬다.

## 10. 검증과 배포 기준

- **단위 테스트:** 문제 검증·채점, 오답 선별, 통계 분모, 레이드 기여량, 오답 상위 문항 계산, 방 만료.
- **권한·통합 테스트:** 학생의 교사 명령 실행, 다른 방 조회, 정답 사전 조회, 조작된 점수 제출, 중복 답안, 종료 후 제출 차단.
- **수업 E2E:** 방 생성 → 학생 3명 입장 → 이해도 체크 → 빠른 확인 → 레이드 → 오답 카드 내보내기 → 종료.
- **개인 학습 E2E:** 가져오기 → 집중 학습 → 오답 → 재도전 → 완료 카드 → 브라우저 재시작 → 기록 복원.
- **장애·성능:** 30명·50명 동시 입장과 답안 제출, 학교 공동 IP, 연결 단절·복구, 교사 새로고침, 사이드바 닫기, 무료 한도 초과 상황.
- **실기기:** 웨일 확장앱, Chrome·Edge 웹앱, 모바일 360px, 전자칠판 화면을 구분해 확인한다.
- **자동 검증:** lint·TypeScript·단위/통합 테스트·웹/확장앱 빌드·Playwright E2E를 CI에 포함한다.

코드 발급 2초, 학생 입장 20초, 일반 수업 집계 반영 1초 이내를 목표로 측정한다. 레이드의 배치 전송 지연은 별도로 기록하며, 실제 측정 없이 목표 달성을 선언하지 않는다.

## 11. 수업 적용·효과 측정

**본선 전에 서로 다른 학년·교과 2개 학급 이상에서 학급별 3차시 이상 적용하고, 집계 데이터만으로 효과를 측정한다.** 협력 교사에게는 빠른 시작 안내만 주고 직접 운영하게 해 활용성도 함께 검증한다.

| 지표 | 측정 방법 |
|---|---|
| 응답 참여율 | 활동별 응답 제출 학생 수 ÷ 입장 학생 수(자동 집계) |
| 재도전 정답률 변화 | 첫 시도 정답률과 오답 재도전 후 정답률 비교 |
| 오답 복습 완료율 | 학습 완료 카드 제출 수 ÷ 학급 인원 |
| 교사 준비·정리 시간 | 기존 방식과 사용 시 형성평가 준비·채점·정리 시간 자기 기록 |
| 학생 인식 | 익명 3문항 설문(재미, 참여 부담, 다시 쓰고 싶은지) |
| 교사 사용성 | 협력 교사 인터뷰, 첫 수업방을 여는 데 걸린 시간 |

학생 이름 없이 학급 단위 집계만 기록하고, 측정하지 않은 효과는 주장하지 않는다. 수업 적용 절차는 소속 학교 기준을 따른다.

## 12. 본선 시연·부스 체험

**참관객이 1분 안에 레이드에 참여하고, 그 결과가 팀보드 카드로 바뀌는 장면까지 직접 보게 한다.**

1. 웨일 클래스 화면을 띄운 채 사이드바에서 수업방을 연다.
2. 참관객 휴대폰으로 QR 입장, 이해도 체크 1회.
3. 3문항 협동 레이드, 전자칠판에 학급 HP 감소 표시.
4. 오답 상위 문항을 팀보드 카드로 내보내는 장면.
5. 학생 화면에서 오늘의 복습과 학습 완료 카드 생성.
6. 수업 적용 결과 차트로 마무리.

부스 체험 모드는 레이드 종료 30초 뒤 새 방을 자동으로 열어 진행자 없이 반복된다. 행사장 네트워크에 대비해 20명 동시 접속 리허설, 휴대폰 데이터 연결, 오프라인 시연 영상을 준비한다.

## 13. 확산 계획과 위험 관리

- **교과 확장:** 문제 엔진은 교과와 무관하다. 교과별 예제 세트와 성취기준 코드로 시작한다.
- **학교급 확장:** 초등 저학년은 OX·객관식 중심, 중등은 단답형과 성취기준별 통계를 강조한다.
- **교사 연수:** 교사가 학생 역할로 레이드를 체험하고 자기 교과 문제 세트를 만드는 실습으로 운영한다.

| 위험 | 대응 |
|---|---|
