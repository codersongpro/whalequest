# Whale Quest 제작 계획 (v0.6)

> NWEC 26 바이브코딩 공모전 출품용 · 분야 1 수업 지원·학습 활동
> v0.5 대비 주요 변경
> - 예선·본선 구분을 없애고 **최종 산출물 하나**를 기준으로 범위·순서·완료 조건을 재구성
> - 웨일 연동을 "링크 허브 + 내보내기"에서 **상황 인식 사이드바(L2)** 중심으로 격상
> - 시연 시나리오를 상황 인식 사이드바 흐름으로 다시 설계하고, 시연 환경·대체 경로를 산출물에 포함

## 1. 목표와 최종 산출물 범위

**웨일 서비스를 오가는 교사 옆에서 사이드바가 다음 할 일을 준비하고, 형성평가 → 협동 레이드 → 모둠 성찰 → 개인 복습이 한 차시 안에서 닫히는 수업 도구를 만든다.**

기준 규모는 **한 학급 30~50명**이다. 아래 범위 전체를 구현하고 실제 수업과 시연 리허설을 통과한 상태를 최종 산출물로 본다.

| 영역 | 최종 산출물에 포함 |
|---|---|
| 상황 인식 사이드바 | 웨일 클래스·팀보드·웨일온·수업 자료 화면을 인식해 모드 자동 전환, 수동 모드 전환 탭 |
| 교사 수업 도구 | 타이머, 랜덤 뽑기, 모둠 편성, 투표, 질문함, 수업 결과 로컬 저장 |
| 수업방 | 코드·QR 입장, 무로그인 참여, 재접속 복구, 전송 대기 표시, 종료 |
| 실시간 활동 | 이해도 체크, 빠른 확인, 형성평가(객관식·OX·단답형), 문항·성취기준별 통계 |
| 협동 레이드 | 보스 HP, 정답 기여, 5분 진행, 전자칠판 표시, 결과 화면, 오답 상위 문항 산출 |
| 문제 관리 | 직접 작성, JSON 가져오기, AI 문제 생성 프롬프트 템플릿, 교사 검수, 성취기준 코드, 공유 링크·QR |
| 개인 학습 | 집중 학습, 오답 복습, 오늘의 복습, 학습 완료 카드, JSON 백업·복원 |
| 웨일 연계 | 4장의 서비스별 연계 기능(L1~L2) |
| 현장 운영 | 교과별 예제 문제 세트 4종, 빠른 시작 안내, 관리자 일괄 배포 가이드, 시연 모드·부스 체험 모드 |

**구현하지 않는 것:** 앱 내부 AI, 결제, 광고, 공개 개인 순위, 개인 아케이드·룰렛·캐릭터 성장 등 게임 확장, 웨일 스토어 공개 등록.

**주최 확인 후 추가하는 것:** 웨일 서비스 화면에 직접 내용을 채워 넣는 기능(L2+), 웨일 스페이스 계정 연동·팀보드 임베드·클래스 외부 도구 등록(L3).

제공 PRD와 [공유 대화](https://chatgpt.com/share/6abcf32a-2acc-83ee-a1db-b59b8d6e992c?no_universal_links=1)에서 확인한 초기 제안·마지막 수정 내용을 반영한다. 공유 페이지의 중간 전체 발화는 확인하지 못했으므로 세부 요구사항은 제공 PRD를 기준으로 한다. 문서 버전은 본 문서(v0.6)로 통일한다.

## 2. 해결하려는 교육 문제

**형성평가가 '하고 끝나는' 활동에 머물고, 수업 도구가 흩어져 수업 흐름이 끊긴다.**

- **결과가 다음 학습으로 이어지지 않는다.** 정답률은 화면에 잠깐 보이고 사라진다. 누가 어떤 개념을 틀렸는지 교사가 다시 정리해야 하고, 틀린 학생은 오답을 다시 볼 기회 없이 다음 차시로 넘어간다.
- **순위 중심 게임이 일부 학생의 참여를 위축시킨다.** 속도와 점수로 경쟁하는 퀴즈는 상위권 몇 명의 무대가 되기 쉽고, 느리거나 자주 틀리는 학생은 참여를 포기한다.
- **도구를 오가느라 수업이 끊긴다.** 웨일 클래스, 팀보드, 웨일온, 퀴즈·타이머 사이트를 오갈 때마다 교사는 무엇을 어디서 해야 하는지 다시 찾는다. 학생은 매번 새로운 접속 방법을 익혀야 한다.

수업 적용 전 교사·학생 사전 설문으로 위 문제를 뒷받침해 기획서에 넣는다(13장).

## 3. 해결 아이디어와 창의적 접근

**차별점은 퀴즈 자체가 아니라, 웨일 서비스를 오가는 동안 사이드바가 수업 순환을 이어 주는 구조다.**

```
① 수업 전 배포      [웨일 클래스 화면] 사이드바: 문제세트 링크·QR·공지 문안 준비
      ↓
② 이해도·형성평가   [수업 자료 화면]   사이드바: 이해도 체크·형성평가 진행, 서버 자동 채점
      ↓
③ 협동 레이드       [웨일온/전자칠판]  사이드바: 전자칠판 모드, 학급 공동 HP, 순위 없음
      ↓
④ 오답 모둠 성찰    [팀보드 화면]      사이드바: 방금 레이드의 오답 3문항 카드 준비
      ↓
⑤ 개인 오늘의 복습  [학생 화면]        오답 재도전 → 학습 완료 카드
      ↓
⑥ 다음 차시 준비    [웨일 클래스 화면] 사이드바: 복습 세트 배포, 오답 기반 다음 차시 문항 추천 → ①
```

- **상황 인식 사이드바:** 교사가 웨일 서비스 탭을 여는 순간, 그 화면에서 할 일이 사이드바에 준비되어 있다. 메뉴를 찾지 않는다.
- **협동 레이드:** 정답 하나하나가 같은 크기로 학급 목표에 기여한다. 개인 순위·콤보 배율이 없고 오답 후 정답도 기여해, 느린 학생도 끝까지 참여한다.
- **오답의 재활용:** 많이 틀린 문항이 팀보드 모둠 토론과 개인 복습, 다음 차시 문항 추천으로 이어진다.

## 4. 웨일 교육 서비스 연계 설계

**Whale Quest는 웨일 서비스를 대체하지 않는다. 교사가 웨일 서비스를 오가는 순간마다 사이드바가 그 화면에 맞는 다음 할 일을 준비한다.**

### 연동 수준 정의

| 수준 | 내용 | 적용 |
|---|---|---|
| L0 링크 허브 | 바로가기, QR, 공유 링크 | 보조 수단 |
| L1 내보내기 | 공지 문안·카드 텍스트·이미지 생성 → 교사가 붙여넣기 | 모든 연계의 기본 동작 |
| **L2 상황 인식** | 사이드바가 현재 탭의 웨일 서비스를 인식해 해당 화면용 기능을 자동 표시 | **최종 산출물의 연동 기준** |
| L2+ 화면 입력 보조 | 웨일 서비스 화면에 "Whale Quest에서 가져오기" 버튼을 띄워 내용 입력 | 주최 허용 시 추가 |
| L3 공식 연동 | 계정 로그인, 임베드, 외부 도구 등록, API | 주최·네이버 협조 시 추가 |

### 상황 인식 사이드바 동작

| 교사가 연 화면 | 사이드바 모드 | 준비되는 기능 | 수준 |
|---|---|---|---|
| 웨일 클래스 | 클래스 모드 | 오늘 문제세트 링크·QR, 과제 공지 문안 원클릭 복사, 오늘의 복습 세트 배포 문안, 지난 수업 오답 기반 다음 차시 문항 추천, 명단 붙여넣기 → 랜덤 뽑기·모둠 | L2 |
| 팀보드 | 팀보드 모드 | 방금 끝난 레이드의 오답 상위 3문항 카드(문항·선택지 분포·토론 질문), 모둠 편성 결과, 익명 질문함 카드. 카드별 복사·이미지 저장 | L2 |
| 웨일온 | 원격 수업 모드 | 전자칠판 화면 열기(화면 공유용), 원격 학생용 입장 QR 크게 보기, 이해도 체크 바로 시작 | L2 |
| 그 밖의 화면(교과서·PDF 등) | 수업 모드 | 타이머, 랜덤 뽑기, 이해도 체크, 형성평가, 레이드 시작 | L2 |
| UBT 평가 화면 | 일시 정지 | 평가 중임을 표시하고 모든 학생 대상 기능 비활성화 | L2 |

- 자동 인식이 안 되거나 교사가 원하면 사이드바 상단 탭(클래스·팀보드·원격·수업)으로 **수동 전환**한다. 시연과 실제 수업 모두 이 경로로 항상 동작을 보장한다.
- 모드가 바뀌어도 진행 중인 수업방·타이머·활동 상태는 유지한다.

### 연계 원칙

- 확장앱은 **현재 탭의 주소만** 확인하고 페이지 내용은 읽지 않는다. 주소 접근 권한은 웨일 서비스 도메인으로 한정한다.
- 학생 개인 데이터를 웨일 서비스로 자동 전송하지 않는다. 팀보드·클래스로 가는 내용은 학급 집계와 문항 정보뿐이며, 교사가 확인 후 게시한다.
- UBT는 총괄·수행평가, Whale Quest는 과정 중심 형성평가와 보충 학습으로 역할을 나눈다.
- 웹 링크만으로도 모든 학생 기능과 교사 기능을 쓸 수 있다. 사이드바는 **웨일에서 쓰면 수업 흐름이 끊기지 않는 이유**로 위치시킨다.

## 5. 화면 역할

| 화면 | 사용자 | 역할 |
|---|---|---|
| 상황 인식 사이드바 | 교사 | 현재 웨일 서비스에 맞는 모드, 수업방·활동 제어, 수업 도구 |
| 교사 대시보드(웹) | 교사 | 문제 편집·가져오기·검수, 학생별 응답, 통계, 내보내기 |
| 학생 홈(웹) | 학생 | '수업 참여'와 '혼자 학습하기'를 명확히 구분. 개인 학습 경로에는 교사용 메뉴 없음 |
| 전자칠판 | 학급 전체 | 학급 집계와 레이드만 표시. 학생별 답안·이해도는 교사 전용 화면에서만 제공 |
| 시연·부스 체험 모드 | 심사위원·참관객 | 시연용 학급·문제 자동 준비, 3문항 레이드 자동 반복(12장) |

- **게임:** 레이드는 React와 SVG/CSS로 구현한다. 문제 출제·채점은 공통 엔진이 담당하고, 게임은 결과를 받아 표현한다.
- **디자인:** 딥블루·시안 계열과 자체 해양 캐릭터를 쓴다. 기능 중심 한글 메뉴, 모바일 큰 버튼, 동작 줄이기를 적용한다. 사이드바 모드마다 색 띠와 아이콘으로 현재 모드를 구분한다.

## 6. 기술 구조

**React + TypeScript + Vite를 공통 기반으로 사용한다.** 정적 웹앱은 Vercel, 실시간 데이터는 Supabase(**서울 리전**), 개인 문제와 학습 기록은 IndexedDB에 저장한다. 서버가 필요 없는 기능(타이머, 모둠, 랜덤 뽑기, 개인 학습)은 실시간 서버에 의존하지 않는다.

| 구성 | 역할 |
|---|---|
| `apps/web` | 학생 참여·개인 학습, 교사 대시보드, 전자칠판, 시연·부스 모드 |
| `apps/extension` | 상황 인식 사이드바, 탭 감지, 모드별 화면, 수업방·활동 제어 |
| `packages/core` | 공통 타입, 문제 검증·채점, 오답 선별, 학습 기록 |
| `packages/handoff` | 웨일 서비스별 전달물 생성(공지 문안, 팀보드 카드 텍스트·이미지, 복습 세트 문안) |
| `packages/context` | 탭 주소 → 모드 판정 규칙, 웨일 서비스 도메인 설정 파일 |

확장앱은 Manifest V3와 `sidebar_action`으로 구성하고, `action`을 함께 선언하지 않는다. 탭 주소 확인은 웨일 서비스 도메인으로 한정한 `host_permissions`로 처리하고, 전체 탭 접근 권한과 콘텐츠 스크립트는 기본 구성에 넣지 않는다. 공식 문서의 설치 조건을 적용한 뒤 실제 웨일에서 검증한다. [웨일 매니페스트 문서](https://developers.whale.naver.com/api/extensions/manifest/)

화면 폭 360px(휴대폰)부터 전자칠판까지 반응형으로 만들고, 사이드바는 390~590px 폭에 맞춘다.

## 7. 핵심 설계

### 상황 인식 모듈

- 탭 전환·주소 변경 이벤트에서 현재 탭 주소를 받아 `packages/context`의 규칙으로 모드를 판정한다.
- 웨일 클래스·팀보드·웨일온·UBT의 실제 도메인과 경로 패턴은 설정 파일로 분리한다. 서비스 주소가 바뀌어도 설정만 고치면 된다.
- 판정 결과는 사이드바 상단에 표시하고, 수동 전환한 모드는 해당 탭에서 우선 적용한다.
- 레이드 결과, 오답 상위 문항, 모둠 편성 결과는 **전달물 보관함**에 쌓아 두고, 해당 모드가 열리면 바로 꺼내 쓴다. 보관함은 교사 기기 로컬에 저장하고 수업방 만료와 함께 정리한다.

### 무로그인 참여와 권한 보호

회원가입·로그인 화면은 만들지 않되, 실시간 기능을 쓸 때 내부적으로 익명 세션을 발급한다. 방 생성자는 교사 권한, 코드로 입장한 사람은 학생 권한을 갖고, 권한은 서버의 방 소유·참여 관계로 판단한다.

- 6자리 코드는 **입장 수단**이며 교사 관리 권한을 주지 않는다.
- 학생은 자기 응답만 제출하고, 다른 학생의 답안이나 교사 화면에 접근할 수 없다.
- 전자칠판에는 집계만 읽는 별도 권한을 부여한다.
- 사이드바에서 웹 대시보드를 열 때는 일회용·단기 연결 코드로 권한을 전달한다. 장기 세션 토큰은 URL에 넣지 않는다.
- 공개 테이블과 실시간 채널에 권한 검사(RLS)를 적용하고 서버 비밀 키는 브라우저 번들에서 제외한다.

Supabase 익명 인증의 기본 IP 제한이 학교 공동망과 행사장 와이파이에서 입장을 막을 수 있다. 동일 IP 50명 입장을 검증하고 제한값·남용 방지를 함께 설정한다. [익명 인증 문서](https://supabase.com/docs/guides/auth/auth-anonymous)

### 문제·답안 인터페이스

PRD의 `AnswerEvent.correct`는 학생이 정답 여부를 조작할 수 있으므로 제거한다.

| 인터페이스 | 결정 |
|---|---|
| `QuestionSet` | JSON 1.0 형식을 유지하고 문제 유형별 정답 형식을 명확히 정의. 문항별 `standard`(성취기준 코드, 예: `[4수01-03]`)와 `tags` 필드 추가 |
| `AnswerSubmission` | 활동 ID, 문제 ID, 실제 답안, 제출 ID, 풀이 시간 전달 |
| 서버 채점 결과 | 정오답·기여량·갱신된 진행 상태 반환. 학생 신원과 태그는 서버에서 확인 |
| `RoomSnapshot` | 현재 활동, 진행 상태, 집계, 레이드 상태, 상태 버전 제공 |
| `HandoffItem` | 전달물 종류(공지·오답 카드·모둠·질문), 대상 서비스, 본문, 이미지, 생성 시각. 학생 식별 정보 없음 |
| 로컬 학습 기록 | 문제 세트 버전과 문제 ID를 함께 저장해 수정 전후 기록 혼동 방지 |

객관식은 선택지 인덱스, OX는 불리언, 단답형은 허용 정답 목록으로 판정한다. 단답형은 유니코드·앞뒤 공백을 정규화하고, 동의어나 수학적 동치는 작성자가 허용 답안으로 지정한다.

JSON 가져오기는 문항별 오류를 보여 주고, **교사가 정답·표현을 확인한 문항만 저장**한다. 외부 생성형 AI에서 바로 이 형식이 나오도록 문제 생성 프롬프트 템플릿을 제공한다. 실시간 활동은 서버가 채점하고, 개인 학습은 같은 규칙으로 로컬 채점한다.

### 실시간 상태와 협동 레이드

- 방에서는 한 번에 하나의 활동을 실행한다. 활동마다 ID를 발급해 이전 활동의 늦은 제출이 섞이지 않게 한다.
- 제출 ID와 출제 회차로 중복 처리를 막는다. 답안 저장·통계·보스 HP 변경은 하나의 트랜잭션으로 처리한다.
- 재접속하면 현재 서버 상태를 다시 읽고 동일 참여자로 복구한다. 확인되지 않은 제출은 '전송 대기'로 표시한다.
- 레이드는 정답당 동일 기여량을 적용한다. 학생별 동일 문제의 피해 기여는 활동당 한 번으로 제한하고, 오답 후 정답 성공도 기여할 수 있게 한다.
- 기본 레이드 시간은 5분, 목표 HP는 시작 인원과 문항 수의 70% 정답 달성량으로 계산한다. 개인 순위와 콤보 배율은 적용하지 않는다.
- 레이드 종료 시 오답 상위 3문항과 선택지 분포를 계산해 전달물 보관함에 넣는다.
- 서버 집계 상태를 최대 초당 한 번 묶어 전송하고 화면에서 부드럽게 보간한다. 개별 답안 전체를 학생들에게 전파하지 않는다.

Supabase Free 한도는 동시 연결 200개·초당 메시지 100개이므로, 운영은 **동시 활성 수업방 1개·학생 최대 50명**으로 제한한다. 사용량과 부하 시험 결과를 확인한 뒤 확대한다. [실시간 제한 문서](https://supabase.com/docs/guides/realtime/limits)

### 개인 학습과 보존 정책

- 오늘의 복습은 최근 오답 → 반복 오답 → 미완료 문항 순으로 구성하며, 기본 20문항으로 중복을 제거한다.
- 오답을 재도전해 맞히면 복습 완료로 표시하고, 다시 틀리면 오답 목록으로 되돌린다.
- 복습을 마치면 정답률, 복습 완료 수, 성취기준 태그가 담긴 학습 완료 카드(이미지)를 만들어 웨일 클래스 과제로 제출할 수 있게 한다. 이름은 학생이 직접 적는다.
- 문제 공유는 서버에 저장한 읽기 전용 문제 세트의 짧은 링크·QR로 구현한다. 학생이 가져온 사본과 기록은 로컬에 유지한다.
- 방은 생성 24시간 후 만료한다. 원시 응답은 종료·만료 24시간 후 삭제하고, 필요한 수업 요약은 교사가 로컬에 저장한다.
- 공유 문제는 기본 30일 후 만료한다. 교사의 원본 문제와 학생이 가져온 사본에는 영향을 주지 않는다.
- 개인 기록은 계정·기기 간 동기화 없이 해당 브라우저에 저장한다. 공용 PC에서는 기록이 남지 않는다는 점을 안내하고 JSON 백업·복원을 제공한다.

## 8. AI 윤리·안전성·연령 적합성

**학생 개인정보를 수집하지 않고, 초등 연령에 맞는 참여 방식을 기본값으로 둔다.**

- **데이터 보호:** 학생은 번호·별명으로 참여하며 실명·연락처·이메일을 받지 않는다. 응답 원본은 24시간 후 삭제하고, 개인 학습 기록은 학생 브라우저에만 저장한다.
- **확장앱 권한 최소화:** 웨일 서비스 도메인의 탭 주소만 확인하고, 페이지 내용은 읽지 않는다.
- **연령 적합성:** 개인 순위를 어디에도 표시하지 않는다. 레이드는 1회 5분 이내로 운영해 과몰입을 막는다. 큰 버튼, 짧은 한글 메뉴, 동작 줄이기로 저학년도 혼자 조작할 수 있게 한다.
- **AI 활용:** 앱 안에서 학생이 AI와 직접 대화하는 기능은 두지 않는다. AI로 만든 문항은 교사 검수 후에만 저장한다.
- **평가 공정성:** UBT 평가 화면에서는 사이드바가 학생 대상 기능을 멈춘다.
- **바이브코딩 투명성:** 개발에 쓴 AI 도구, 주요 프롬프트, 사람이 검토·수정한 지점을 개발 기록으로 남긴다. AI가 만든 코드는 보안·개인정보 점검표를 통과한 뒤 배포한다.

## 9. 개발 순서와 단계별 완료 조건

**한 차시 순환을 먼저 끝까지 연결한 뒤 기능을 넓히고, 실제 수업과 시연 리허설로 마무리한다.** 각 단계의 완료 조건을 통과해야 다음 단계로 넘어간다. 날짜는 공모 일정 확인 후 채운다.

| 단계 | 구현 내용 | 완료 조건 |
|---|---|---|
| 1. 준비 | 주최 측 연계 문의(L2+·L3, 웨일 서비스 도메인), 사전 설문, `QuestionSet`·`HandoffItem` 확정, 작업공간 구성 | 연계 허용 범위와 서비스 도메인 확인, 데이터 형식 확정 |
| 2. 사이드바·상황 인식 | MV3 사이드바, 탭 감지, 모드 판정 설정 파일, 수동 전환, 모드별 빈 화면 | 실제 웨일에서 클래스·팀보드·웨일온·일반 탭 전환 시 모드가 바뀌고, 탭을 오가도 사이드바가 유지됨 |
| 3. 수업 도구 | 타이머, 랜덤 뽑기, 모둠 편성, 명단 붙여넣기, QR 저장 | 서버 없이 동작, 모드 전환·사이드바 닫기 후에도 상태 유지 |
| 4. 실시간 수업방 | 익명 세션, 권한, 코드·QR, 입장·종료·재접속 | 교사 1명·학생 3명 연결, 타인 방 접근 차단, 재접속 복구 |
| 5. 참여 활동·평가 | 이해도 체크, 빠른 확인, 형성평가(3개 유형), 문제 편집·가져오기·검수, 프롬프트 템플릿, 통계 | 3개 유형 채점과 문항·성취기준별 통계 검증 |
| 6. 협동 레이드 | 서버 상태, HP·기여량, 전자칠판, 결과, 오답 상위 문항 산출 | 동시 제출·중복 방지 검증 |
| 7. 전달물·웨일 연계 | 전달물 보관함, 클래스 모드(공지·복습 세트·다음 차시 추천), 팀보드 모드(오답 카드 텍스트·이미지), 원격 수업 모드, UBT 일시 정지 | 수업 모드에서 레이드 → 팀보드 탭 전환 시 오답 카드가 준비되어 있음 |
| 8. 개인 학습 | 학생 홈, 집중 학습, 오답·오늘의 복습, 학습 완료 카드, 공유, 백업·복원 | 수업방 없이 학습, 브라우저 재시작 후 기록 유지 |
| 9. 현장 마감 | 투표·질문함, 결과 저장, 접근성, 예제 세트 4종, 빠른 시작 안내, 관리자 배포 가이드 | 처음 보는 교사가 안내문만 보고 5분 안에 첫 수업방을 엶 |
| 10. 수업 적용 | 2개 학급 이상, 학급별 3차시 이상 적용, 측정 지표 수집 | 13장 지표 수집, 문제점 수정 반영 |
| 11. 시연 완성 | 시연 모드, 부스 체험 모드, 시연 영상, 리허설 | 12장 시연 시나리오를 3회 연속 끊김 없이 완주, 부스 20명 동시 체험 통과 |

수업 적용(10단계)은 7단계가 끝나는 즉시 본인 학급부터 시작해 8~9단계와 병행한다. 대시보드는 마지막에 한꺼번에 만들지 않고 각 활동과 함께 확장한다. L2+·L3 연계는 주최 확인 결과에 따라 7단계에 추가한다.

## 10. 검증 기준

- **단위 테스트:** 문제 검증·채점, 오답 선별, 통계 분모, 레이드 기여량, 오답 상위 문항 계산, 모드 판정 규칙, 방 만료.
- **권한·통합 테스트:** 학생의 교사 명령 실행, 다른 방 조회, 정답 사전 조회, 조작된 점수 제출, 중복 답안, 종료 후 제출 차단, 전달물에 학생 식별 정보 미포함.
- **수업 E2E:** 방 생성 → 학생 3명 입장 → 이해도 체크 → 형성평가 → 레이드 → 팀보드 모드 오답 카드 → 클래스 모드 복습 세트 배포 → 종료.
- **개인 학습 E2E:** 가져오기 → 집중 학습 → 오답 → 재도전 → 완료 카드 → 브라우저 재시작 → 기록 복원.
- **상황 인식 실기기 시험:** 실제 웨일에서 서비스별 탭 전환, 새 창·새 탭, 주소 변경, 수동 전환 우선 적용, 인식 실패 시 수업 모드 유지.
- **장애·성능:** 30명·50명 동시 입장과 답안 제출, 학교 공동 IP, 연결 단절·복구, 교사 새로고침, 사이드바 닫기, 무료 한도 초과 상황.
- **실기기:** 웨일 확장앱, Chrome·Edge 웹앱, 모바일 360px, 전자칠판 화면을 구분해 확인한다.
- **자동 검증:** lint·TypeScript·단위/통합 테스트·웹/확장앱 빌드·Playwright E2E를 CI에 포함한다.

코드 발급 2초, 학생 입장 20초, 일반 수업 집계 반영 1초 이내를 목표로 측정한다. 레이드의 배치 전송 지연은 별도로 기록하며, 실제 측정 없이 목표 달성을 선언하지 않는다.

| 바이브코딩 개발 기록 | 문서 | AI 도구·프롬프트·사람 검토 지점 기록 |
| 수업 적용 보고서 | 문서 + 집계 차트 | 13장 지표를 2개 학급 이상에서 수집 |
| 시연 키트 | 시연 모드 데이터, 시연 체크리스트, 대체 경로 | 12장 리허설 3회 연속 완주 |
| 부스 체험 키트 | QR 포스터, 3문항 세트, 안내 카드 | 20명 동시 체험 리허설 통과 |

제출 형식이 공모 요강과 다르면 요강을 우선한다.

## 12. 시연 시나리오

**한 대의 웨일 브라우저에서 탭만 바꾸며 한 차시 순환을 보여 주고, 탭을 바꿀 때마다 사이드바가 그 화면에 맞게 바뀌는 장면을 핵심 컷으로 삼는다.** 목표 시간은 3분이다.

### 시연 흐름

| 순서 | 교사가 연 화면 | 사이드바에서 보이는 것 | 참관객·심사위원이 하는 것 |
|---|---|---|---|
| 1 | 웨일 클래스 수업 화면 | 클래스 모드: 오늘 문제세트, 공지 문안 원클릭 복사 | 복사한 문안이 클래스 공지에 게시되는 것을 봄 |
| 2 | 수업 자료(교과서 화면) | 수업 모드: 수업방 열기 → 입장 QR | 휴대폰으로 QR 입장, 이해도 체크 응답 |
| 3 | 웨일온(또는 전자칠판 화면) | 원격 수업 모드: 전자칠판 열기 | 3문항 협동 레이드 참여, 학급 HP가 줄어드는 것을 봄 |
| 4 | 팀보드 | 팀보드 모드: 방금 레이드의 오답 3문항 카드가 이미 준비됨 | 카드가 팀보드에 붙고 모둠 토론 질문이 생기는 것을 봄 |
| 5 | 학생 화면(휴대폰) | — | 오답 재도전 → 학습 완료 카드 생성 |
| 6 | 웨일 클래스 | 클래스 모드: 오늘의 복습 세트 배포 문안, 다음 차시 추천 문항 | 순환이 다시 ①로 닫히는 것을 봄 |
| 7 | 시연 화면 | — | 수업 적용 결과 차트 1장으로 마무리 |

4번이 가장 중요한 장면이다. 교사가 아무것도 찾지 않았는데 팀보드 탭을 여는 순간 오답 카드가 준비되어 있어야 한다.

### 시연 모드

- 시연용 학급, 예제 문제 세트, 웨일 서비스 탭 묶음(클래스·자료·웨일온·팀보드)을 한 번에 여는 **시연 시작** 버튼을 제공한다.
- 시연용 웨일 클래스·팀보드 공간을 미리 만들어 두고, 시연 후 원래 상태로 되돌리는 정리 절차를 체크리스트로 둔다.
- 시연 모드의 문제·결과는 실제 학생 데이터와 섞이지 않게 별도 방으로 운영한다.

### 부스 체험 모드

- 3문항 레이드가 끝나면 30초 뒤 새 방이 자동으로 열려 진행자 없이 반복된다.
- 대형 화면에는 입장 QR과 학급 HP를 크게 보여 부스 밖에서도 진행 상황이 보인다.
- 체험이 끝날 때마다 팀보드 모드의 오답 카드 화면으로 자동 전환해, 연계 장면을 반복해서 보여 준다.
- 체험한 참관객에게 예제 문제 세트와 빠른 시작 안내로 연결되는 QR 카드를 준다.

### 시연 환경과 대체 경로

- 행사장 와이파이는 동일 IP 다수 접속이 발생한다. 익명 인증 제한값을 조정하고 20명 동시 접속 리허설을 한다.
- 자동 인식이 실패하면 사이드바 상단 탭으로 수동 전환한다. 시연 체크리스트에 전환 위치를 표시한다.
- 웨일 서비스 로그인이 풀리거나 접속이 안 되면, 같은 흐름을 담은 시연 영상으로 즉시 대체한다.
- 휴대폰 데이터 연결을 예비 네트워크로 준비한다.

## 13. 수업 적용·효과 측정

**서로 다른 학년·교과 2개 학급 이상에서 학급별 3차시 이상 적용하고, 집계 데이터만으로 효과를 측정한다.** 협력 교사에게는 빠른 시작 안내만 주고 직접 운영하게 해 활용성도 함께 검증한다.

| 지표 | 측정 방법 |
|---|---|
| 응답 참여율 | 활동별 응답 제출 학생 수 ÷ 입장 학생 수(자동 집계) |
| 재도전 정답률 변화 | 첫 시도 정답률과 오답 재도전 후 정답률 비교 |
| 오답 복습 완료율 | 학습 완료 카드 제출 수 ÷ 학급 인원 |
| 교사 준비·정리 시간 | 기존 방식과 사용 시 형성평가 준비·채점·정리 시간 자기 기록 |
| 도구 전환 부담 | 수업 중 교사가 메뉴·사이트를 찾느라 멈춘 횟수 자기 기록(기존 방식 대비) |
| 학생 인식 | 익명 3문항 설문(재미, 참여 부담, 다시 쓰고 싶은지) |
| 교사 사용성 | 협력 교사 인터뷰, 첫 수업방을 여는 데 걸린 시간 |

학생 이름 없이 학급 단위 집계만 기록하고, 측정하지 않은 효과는 주장하지 않는다. 수업 적용 절차는 소속 학교 기준을 따른다.

## 14. 확산 계획과 위험 관리

- **교과 확장:** 문제 엔진은 교과와 무관하다. 교과별 예제 세트와 성취기준 코드로 시작한다.
- **학교급 확장:** 초등 저학년은 OX·객관식 중심, 중등은 단답형과 성취기준별 통계를 강조한다.
- **교사 연수:** 교사가 학생 역할로 레이드를 체험하고 자기 교과 문제 세트를 만드는 실습으로 운영한다.
- **서비스 확장:** 상황 인식 규칙이 설정 파일로 분리되어 있어, 다른 웨일 교육 서비스도 모드 추가만으로 연결할 수 있다.

| 위험 | 대응 |
|---|---|
| 웨일 서비스 도메인·주소 구조 변경 | 모드 판정 규칙을 설정 파일로 분리, 수동 전환으로 항상 동작 보장 |
| L2+·L3 연계 불허 | L2 상황 인식 + L1 내보내기로 최종 산출물 완성 |
| 개발 범위 초과 | 9장 순서 유지, 한 차시 순환(2~7단계)을 먼저 완성하고 나머지는 범위 축소 |
| 학교 공동망·행사장 IP 제한 | 익명 인증 제한값 조정, 50명 동시 입장 사전 시험 |
| Supabase 무료 한도 | 동시 수업방 1개·50명 제한, 사용량 모니터링 |
| 수업 적용 기간 부족 | 7단계 완료 즉시 본인 학급부터 적용 |
| 공용 PC 개인 기록 손실 | JSON 백업·복원, 1인 1기기 환경 안내 |
| 시연 중 네트워크·로그인 문제 | 수동 전환, 예비 네트워크, 시연 영상 대체 |
