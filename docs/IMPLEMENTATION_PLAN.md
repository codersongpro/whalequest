# Whale Quest 구현 기준 (v0.6)

2026-10-01. [수정 계획 v0.6 원본](reference/whale-quest-plan-v0.6.md)을 최우선 설계 기준으로 보관했다. v0.4/v0.5 원본은 역사 자료이며 예선/본선 관문A/B 구분은 폐기했다. 앱 버전은 변경하지 않았다.

## 현재 승인 범위

사용자는 본선 범위를 나누지 말고 전부 구현하고, 웨일 서비스와 연결된 시연을 요구했다. 이어 Supabase 프로젝트가 없으므로 **시연 모드와 연결 준비까지** 진행하라고 답했다. v0.6은 하나의 최종 산출물·L2 상황 인식 중심으로 변경됐다. 후속 기능을 페이즈마다 중단하던 이전 요청은 최신 요청이 대체한다. 실제 수업 적용/주최 문의 발송/출품/공개 배포는 별도 작업이다.

## 제품과 범위

문제: 평가 결과의 단절, 개인 순위 중심 참여 부담, 분산 서비스의 전환 비용. 클래스 배포 → 평가 → 협동 레이드 → 팀보드 성찰 → 개인 복습/완료 카드 → 다음 차시 준비 순환을 구현한다. 교사가 다음 활동을 결정한다. 부스 반복만 자동 전환 예외다.

최종 대상은 수업 도구/방/3유형 평가/통계/레이드/문제관리/공유/개인복습/전달물/시연·부스/4교과 예제/운영 안내다. 개인 아케이드·룰렛·성장·앱 내부 AI·결제·광고·공개 개인 순위·스토어 공개 등록은 제외한다. L2+ 화면 입력과 L3 계정/임베드/API 연동은 주최 허용 후 추가하며 현재 구현하지 않는다.

L0 링크는 보조, L1 텍스트/PNG 수동 게시가 기본, L2는 현재 탭 주소로 모드 전환/전달물 준비. 클래스·팀보드·원격·수업 수동 전환 제공, UBT 판정은 수동 모드로 우회할 수 없게 잠근다. 모드만 바뀌며 수업방·타이머·전달물은 유지한다. 자동 인식/실제 사이드바 연결은 웨일 실기기 완료 기준을 통과해야 한다.

## 구조와 근거

React/TypeScript/Vite 유지. packages/core는 3유형 공통 채점·JSON1.0/기존 PRD 변환·IndexedDB 기록. packages/context/service-domains.json은 URL의 정확한 호스트로 판정하며 DOM을 읽지 않는다. packages/handoff는 로컬 집계 전달물·텍스트/PNG·오답 복습 세트 추천. packages/classroom은 동일 브라우저 시연이고 packages/server는 익명 인증/RPC 준비다.

클래스/팀보드 기본 호스트는 공식 도움말에서 확인한 주소다. 웨일온은 스터디 웹 주소와 수동 원격 전환을 사용하며 네이티브 웨일온 자동 감지를 보장하지 않는다. UBT는 ubt.whalespace.io 전체를 보수적으로 잠그는 규칙이며 정확한 평가 경로와 주최 범위 확인이 남았다.

- 클래스 공식 링크: https://help.whale.naver.com/ko/whaleclass/
- 팀보드 공식 로그인: https://help.whale.naver.com/ko/whalespace/teamboard/gettingstarted/login/
- 확장 iframe 저장소 분리: https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies

MV3 sidebar_action, action/tabs/content_scripts 없음. host_permissions는 서비스 호스트로 제한하며 빌드된 VITE_PUBLIC_APP_URL이 있으면 **자체 앱 호스트1개**를 iframe 저장소 공유 목적으로 추가한다. Chrome 문서의 저장소 분리 때문에 필요한 구현 결정이며 전체 사이트 권한을 추가하지 않는다. 웨일 실제 동작 확인 필요. 웹 frame-ancestors의 extension 스킴 허용은 시연용이며 운영은 확장ID로 제한해야 한다.

## 데이터와 채점

내부 QuestionSet은 schemaVersion 1.0, 세트id/version(정수), 문항id/type/prompt/options/answer/tags/standard를 사용한다. 기존 PRD version 1.0/underscore 유형/question/choices도 가져오기 변환을 지원한다. 원본 데이터 요구와 내부 구조를 구분한다. 가져오기는 문항별 오류, 교사 확인 문항만 저장. 예제 standard는 교사 검수용 목표이며 **공식 교육과정 코드 검증이 완료된 예제가 아니다.**

객관식 인덱스·OX 불리언·단답 허용 목록/NFKC/앞뒤 공백을 공통 판정한다. 수업 시연은 로컬 모형이 채점하며 운영은 서버가 실제 답을 채점해야 한다. 학생 correct/점수를 신뢰하지 않는다. 시연도 활동ID/중복제출/기여 1회·늦은 제출 방지를 적용하되 로컬 저장소의 권한을 운영 보안으로 주장하지 않는다.

방 현재활동1개, 레이드 정답 동일 기여, 오답→정답도 기여, 활동당 학생·문항1회. 기본5분, 시작인원×문항수×70%로 HP 계산, 순위/콤보 없음. 오답 상위3/선택분포는 첫 시도로 집계하고 이름/개별 단답을 카드에 넣지 않는다. 질문 자유 서술은 교사 개인정보 검수 후 게시한다. 모둠 전달물은 이름 없이 인원수/과제 안내를 공유한다.

개인 기록에 세트 버전·문항ID 저장, 최근 미해결 오답 우선·반복오답·미학습 기본20/중복제거. 정답 재도전은 완료. 수업 학생은 자기 제출만 명시적으로 개인 기록에 복사해 복습한다. 시연 공유 브라우저의 개인 IndexedDB는 체험자 간 함께 보일 수 있으므로 실제 개인정보를 넣지 않는다. 운영은 개인 브라우저 기준, 자동 교사 공유 없음.

완료 카드 이름은 선택 직접 입력/저장하지 않음. 공용 PC에서는 기록이 실제로 남을 수 있으므로 백업/삭제를 안내한다. v0.6 원문의 ‘기록이 남지 않는다’/‘개인정보를 수집하지 않는다’를 구현 보장으로 쓰지 않는다. 번호/별명/응답은 처리 데이터며 명단·질문·카드의 공개 경계를 검수한다.

방 생성24시간 만료, 원시 응답은 종료/만료24시간 뒤 정리, 전달물은 방 만료와 함께 정리, 공유30일 만료. 시연은 해당 방/전달물/공유 자료를 읽을 때 만료 항목을 정리하며 전체 저장소의 정기 삭제는 구현하지 않았다. 운영은 서버 정리 작업/접근차단 검증이 필요하다. JSON 백업 복원은 전체 검증 뒤 한 트랜잭션, 계정/기기 동기화 없음.

## 운영/검증 완료 기준

운영 Supabase 서울 리전·익명 세션·소유/참여 권한·RLS·정답 비공개·단기 교사 연결 코드·실제 서버 채점·재접속/전송 대기·실시간 snapshot/버전·50명/IP 시험은 아직 연결 준비다. SQL 초안을 적용 완료한 마이그레이션으로 쓰지 않는다. 실제 학생/타인 방/보스 트랜잭션/동시 제출은 서버 환경에서 재검증한다. 원본의 무료 수치/일정은 이번 변경에서 최신 확정한 값이 아니다.

최종 완성은 2개 다른 학년/교과 학급 각각3차시, 50명 수업/20명 부스, 웨일 실기기, 3분 시연3회, 제출 형식·영상·적용 차트·배포/운영 안내까지다. 현재 브라우저 E2E/모의 HTTP와 별도다. 교사 첫방5분, 코드2초·입장20초·집계1초는 실측 목표.

자료: v0.6 원본 10~14장과 REMAINING_WORK. 교육 효과는 참여율·재도전정답률·완료카드제출률·교사시간/전환중단횟수·익명설문·교사사용성으로 실제 측정하며 미수집 결과를 만들지 않는다.
